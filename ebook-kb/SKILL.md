# 电子书知识库 (ebook-kb)

把电子书变成可随时检索的本地知识库，写稿、做研究时直接引用书中观点和案例。

## 知识库存储位置

所有生成的知识库统一放在一个可配置的根目录（下称 `<KB_ROOT>`，由用户指定或默认当前工作目录下的 `知识库/`），每本书一个独立文件夹：

```
<KB_ROOT>/<书名>/
├── index.md          # 全书索引：字数、章节标记、文本块列表
├── summary.md        # 核心摘要：全书主要观点、框架、金句
├── raw.txt           # 原始全文备份
└── chunks/           # 分块文本，用于检索
    ├── chunk_001.md
    ├── chunk_002.md
    └── ...
```

## 流程一：新建知识库（用户扔一本书过来时）

当用户说"把这本书做成知识库"、"蒸馏这本书"并给出文件路径时：

### 步骤1：提取文本
```bash
python <skill_dir>/scripts/extract_book.py <输入文件路径> "<KB_ROOT>/<书名>/raw_extracted.txt"
```
- 支持 `.pdf` 和 `.epub` 格式
- 书名从文件名自动提取，去掉扩展名

### 步骤2：切块建索引
```bash
python <skill_dir>/scripts/build_kb.py "<KB_ROOT>/<书名>/raw_extracted.txt" "<KB_ROOT>/<书名>"
```
这会自动生成 `chunks/` 目录和 `index.md` 索引文件。

### 步骤3：生成核心摘要
读取 `index.md` 了解全书结构，然后抽样阅读若干个chunk（开头、中间、结尾各抽几个），生成一份 `summary.md`：
- 全书核心论点/主题（3-5条）
- 主要章节框架
- 关键数据和案例清单
- 金句/可引用观点列表
- 可复用的观点、类比与素材点标注

把摘要写入 `<KB_ROOT>/<书名>/summary.md`。

### 步骤4：完成确认
告诉用户：
- 知识库路径
- 总字数、分块数
- 一句话内容概括
- 以后怎么查（直接问就行）

## 流程二：查询已有知识库

当用户问"那本书里关于XX是怎么说的"、"书里有没有提到XX案例"时：

### 步骤1：确认是哪本书
如果用户没说清楚是哪本，先列一下 `<KB_ROOT>/` 下有哪些书，让用户选。

### 步骤2：关键词检索
用 Grep 在 `<KB_ROOT>/<书名>/chunks/` 目录下搜索关键词：
```
Grep pattern="关键词" path="<KB_ROOT>/<书名>/chunks" output_mode="content" -C 3
```
多个相关关键词分开搜。

### 步骤3：精读相关段落
根据Grep结果，Read 命中的具体chunk文件，找到上下文完整的段落。

### 步骤4：回答
- 直接引用书中原文或观点
- 标注大概在哪个位置（哪个chunk/大致章节）
- 不要编造书里没有的内容；如果搜不到，明确说"这本书里没找到相关内容"

## 注意事项

- **不要修改原始电子书文件**，只读不写
- 扫描版PDF可能提取效果差（全是图片），如果提取出来字数太少（比如全书不到1000字），要提醒用户这可能是扫描版，需要OCR
- 知识库建好后，用户以后再提这本书，直接走查询流程，不要重复构建
- 如果用户说"再加一本书"，走流程一，新建独立文件夹
